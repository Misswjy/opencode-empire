# Agent Prompt 精修（三）设计

> 2026-05-27 — 继续在现有 prompt 结构内增强三类模板：六部派工单、司礼监汇总复奏、内阁票拟封驳/暂缓分支。

## 背景

当前 prompt 已经具备较清楚的流程边界和多角色分工，但还有三处决策与执行衔接点可以继续强化：

1. `【六部派工单】` 已有统一字段，但未明确六部各自收到工单时应关注的派发重点。
2. `司礼监` 负责汇总诸部回奏，但目前没有稳定的“汇总复奏模板”，多部门场景下的上呈结构仍可能漂移。
3. `【内阁票拟】` 偏向“建议准行”，但复杂任务中常见的“封驳”或“暂缓办理”分支还不够显式。

本轮继续遵守现有约束：不新增 agent，不调整 agent id 或模式，不拆新的 prompt 文件结构。

## 目标

1. 让六部派工单更像对口下达的工程工单，而不是泛化任务描述。
2. 让司礼监在多部门回奏后的上呈更稳定、更像中枢汇总。
3. 让内阁能够自然输出“建议准行 / 封驳 / 暂缓”的决策分支。

## 方案

### 六部派工单增强

保留统一的 `【六部派工单】` 框架，但新增“分部派发提示”字段，要求内阁在派工时按部门写清不同口径：

- 吏部：交付目标、职责边界、验收标准
- 户部：搜索范围、相关目录、依赖或调用链目标
- 礼部：规格、文案、交互表达的审查范围
- 兵部：执行顺序、并发关系、回滚条件
- 刑部：审查范围、准行条件、必须验证项
- 工部：改动范围、落地目标、验证要求、禁止顺手扩散

### 司礼监汇总复奏模板

在 `eunuch` prompt 中增加一个专用模板，字段包括：

- 汇总结论
- 各部回奏摘要
- 已核实证据
- 仍存分歧
- 风险与请旨事项
- 建议下一步

### 内阁票拟分支增强

在 `【内阁票拟】` 中新增决策分支字段，明确：

- 是否建议准行
- 若不宜准行：封驳理由
- 若建议暂缓：暂缓条件 / 先决信息

这样 `内阁` 不必默认朝执行推进，而能在需求不明、风险过高或验证不足时稳定输出工程性拦截。
