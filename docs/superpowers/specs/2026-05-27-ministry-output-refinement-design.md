# 六部专业化复奏精修设计

> 2026-05-27 — 强化户部、刑部、工部的专业化输出骨架，让三部复奏更像探索报告、code review 与实现交付说明。

## 背景

当前六部已经拥有差异化职责和一些必须附带字段，但 `【本部复奏】` 在三类高价值场景中仍偏简略：

1. 户部的探索结果还不够像探索报告，缺少“当前观察结论”和“建议下一步调查”。
2. 刑部虽然有“是否准行”“问题严重性”等要求，但还不像 code review 那样有问题分级和处理顺序。
3. 工部的实现回奏还缺少更完整的交付说明，例如变更摘要、未覆盖场景等。

本轮继续保留统一的 `【本部复奏】`，只通过规则层增强三部的复奏结构，不拆成独立模板。

## 目标

1. 让户部复奏更像 repo exploration report。
2. 让刑部复奏更像带分级的 code review。
3. 让工部复奏更像实现交付说明与验证记录。

## 方案

### 户部

在 `MINISTRY_RULES` 中明确要求复奏应附：

- 相关文件
- 调用链
- 依赖关系
- 当前观察结论
- 未确认点
- 建议下一步调查

### 刑部

在 `MINISTRY_RULES` 中明确要求复奏应附：

- 是否准行
- 总体结论
- 阻断问题
- 重要问题
- 一般问题
- 缺失验证
- 建议处理顺序

### 工部

在 `MINISTRY_RULES` 中明确要求复奏应附：

- 改动文件
- 变更摘要
- 验证结果
- 未覆盖场景
- 剩余风险
- 未完成项
