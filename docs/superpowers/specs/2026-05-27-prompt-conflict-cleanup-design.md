# Prompt 字段去冲突整理设计

> 2026-05-27 — 收口 agent prompt 中残留的字段重复、决策分支冲突与共享约束不一致问题。

## 背景

随着多轮精修，prompt 的信息密度已经很高，但也出现了三类结构性问题：

1. `内阁票拟` 的决策字段并列堆叠，缺少互斥规则，模型可能同时给出互相冲突的结论。
2. `封驳理由` 与 `风险与封驳点` 有语义重叠，边界不清。
3. `buildWorkflow()` 与 `buildSubWorkflow()` 的共享工程规则口径不一致，导致主代理与子代理看到不同版本的底层约束。

本轮不新增 agent，不继续扩模板，只做去冲突整理。

## 目标

1. 让 `内阁票拟` 的决策分支具有明确互斥关系。
2. 去掉或重命名语义重叠字段。
3. 统一主流程与子流程共享的工程规则。

## 方案

### 1. 内阁票拟分支互斥化

在 `cabinet` 规则文案中明确：

- `是否建议准行`
- `是否需先补调查`
- `封驳理由`
- `暂缓条件`

不是并列自由填写，而是根据单一主结论选择性填写。

### 2. 风险字段去重

保留 `封驳理由`，将 `风险与封驳点` 改名为 `主要风险`，避免两者反复表达同一件事。

### 3. 共享约束统一

将工程事实优先、可直接办理 / 必须请旨边界等规则作为共享底层约束，同时注入主流程与子流程。主子流程只保留流程线和批红描述的差异。

## 影响文件

- 修改：`src/prompts.ts`
- 修改：`src/prompts/cabinet.md`
- 修改：`src/__tests__/agents.test.ts`
